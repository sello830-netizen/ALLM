# بروتوكول التجارب

1. يحدد كل run فرضية ومتغيرًا رئيسيًا وضوابط قبل التشغيل.
2. تثبت نسخة البيانات والتقييم والإعدادات والـseed.
3. لا تقارن runs إذا اختلفت نسخة metric أو split دون توضيح.
4. الإعادة لا تستبدل run السابق؛ تستخدم `parent_run_id`.
5. تحفظ المقاييس الخام والتكلفة وحالة run.
6. أي قرار Go/No-Go يربط بالـrun IDs والتقرير الناتج.
